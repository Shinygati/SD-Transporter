# iPhone Pokewalker companion

Native SwiftUI iPhone source using the same portable `shared/walkerfile.c` and species-name core as Android, NDS and 3DS. Requires iOS 16 or later. No game ROM, retail firmware or sprite sheet is bundled. The display decodes the original 64 × 48 bitmap from your own walker without cropping it.

Implemented source includes Radar grass and timed rustles, battles/catching, Dowsing, pack replacement, trainer/route/step information, physical and optional simulated walking, saved console IP addresses, local Wi-Fi ownership transfer and verified recovery snapshots. This initial iOS port has not yet been built with an Apple SDK or tested on an iPhone; Windows syntax checks and shared-core tests do not establish iOS runtime compatibility.

## Walking

Physical steps are the default; simulated walking is off by default and uses one step per ten seconds when enabled. Core Motion permission is optional. Historical physical-step queries can catch up while the app was closed, for up to the seven days available from iOS, and only from the current phone handoff/step-source baseline. The cumulative credited count and walker data are committed together to prevent counting the same query twice.

The simulated timer counts only while the app is active. iOS suspension does not keep it running. Switching back to the app resumes its clock without adding simulated background time. Real-device validation is still required for permissions and historical pedometer behaviour.

## Ownership and recovery

Open Phone sync on the NDS/3DS companion, then enter its IPv4 address in the iPhone app. Both devices must be on the same local Wi-Fi. There is no pairing code. Local HTTP port 30820 matches existing consoles and is unencrypted; the app discloses this before first use. Session tokens and CRC32 check framing/identity but are not encryption or protection against an observer on the network.

A pending receive token is saved before contacting the console. A pending return freezes walking and activities before upload, and remains pending until the matching console acknowledgement. Retries use the same token. A console-revoked phone session cannot be returned; preserve/export the phone copy and perform a fresh handoff after console recovery. A currently active phone walker cannot be replaced through Receive.

Immutable byte-verified recovery copies are created before replacing/returning a walker and after receiving one. Export them in Settings using the share sheet. They are earlier snapshots, not a guarantee against every storage failure. The app never automatically activates an old recovery file. It excludes its private data from iCloud device backup to avoid silently cloning active ownership; return and export your walker before uninstalling, reinstalling or changing signing identity.

## Build on macOS

Install a current stable Xcode with its iOS SDK and command-line tools. Keep `ios/` and `shared/` as siblings. The checked-in project is reproducibly generated by `python3 ios/tools/make_project.py`; regeneration requires no third-party Python modules. Open `ios/Pokewalker.xcodeproj`, select the Pokewalker scheme, set your Apple development team for a signed device build, and build for an iPhone. Never commit signing keys or provisioning profiles.

For an unsigned IPA intended for a sideloading tool to sign:

```sh
sh ios/tools/build-ipa.sh
```

Expected output: `ios/build-local/Pokewalker-unsigned.ipa`. An unsigned IPA does not install directly; an authorised signing/sideloading tool must sign it. Actual Xcode compilation and device tests remain required. The `ci/build-ios.yml` template can be copied to `.github/workflows/` by the owner to enable a manual macOS build; it has not been enabled or run on GitHub.

## Install from Windows

Build the IPA on a Mac or a macOS CI runner first. Windows can then use AltServer/AltStore Classic to sign and install it on the owner's iPhone. Follow the official Windows setup instructions, including Apple software and Developer Mode where required. Free Apple accounts generally need refreshing every seven days; keep AltServer available for refresh. Expired signing can prevent launch without deleting app data, but uninstalling can remove app-private walker progress. Return/export first.

Build and type-check using the real iOS SDK, inspect the archive privacy report and required-reason API manifest, verify App Transport Security compatibility with numeric console IPs, run phone/console interrupted-transfer and conflict tests, test Motion permission refusal, inspect all screens at large fonts, and verify signed IPA installation/refresh. ## Registered empty walkers and confirmed returns

Registered empty walkers with valid uploaded joining-course data may now walk and gain the original designated course companion. Blank/unregistered or malformed files remain blocked, and joining cannot replace a companion already aboard. Console/phone handoffs permit the expected empty-to-generated-companion transition while retaining trainer, device, course and session checks. The companion event scheduler is an app implementation; original firmware timing is not claimed.

Update the phone and console companions together. The phone requires either `X-Walker-Stored-CRC32` or a structured session-bound `PWRETURN1` receipt matching its returned EEPROM before clearing active ownership; until confirmation succeeds the phone keeps a frozen pending-return copy. Verified immutable recovery exports are retained. DS Lite Wi-Fi scanning cannot accept a handoff, and active/phone-owned walkers block Wi-Fi reconfiguration.

## Recovery and save integrity (1.3 test)

Confirmed handoffs remove the sender's active Pokémon. Unconfirmed copies remain locked; history snapshots never load automatically. Recovery snapshots are limited to **10 per walker**, oldest first after a newly written snapshot is verified. Console files are grouped by original walker path; phones group by the stable device/trainer identity rather than the handoff token. Ownership receipts and in-flight `.phone` snapshots are not part of the history cap.

3DS/NDS Settings **X** opens the recovery manager. The file list **SELECT** finds histories even when the active file is missing. **Y** changes walker history, **L/R** changes copy, **A** deletes a snapshot after confirmation and **X** deletes the active file after preserving a verified snapshot. **SELECT** inside Recovery offers explicit missing-file recovery from verified `.tmp`, `.replace-old`, `.bak` or `.bak.tmp` candidates. Choose with **L/R**, inspect trainer/pack details and press **A** to restore; candidates are kept, and no phone lock is bypassed. Mobile Settings offers export/delete histories and confirmed active deletion.

Console saves reread the final filename after replacement. FAT/3DS replacement keeps an old-file rollback instead of deleting the target first. Catches and item finds get their own verified recovery snapshot; success is shown only after the active save succeeds. Mobile reward saves follow the same verification rule. Trainer previews show the verified HGSS trainer name and public five-digit Trainer ID where available.

Fault checks cover failed and silently dropped writes, rollback failures, explicit backup restoration and journal replay. Use at your own risk and keep independent backups. iPhone source changes have host C and Swift syntax checks only, not an Apple SDK build.

Companion 1.4 adds named phone profiles with all-active walking and trainer-name/public-ID binding. Console Recovery uses START to restore a selected snapshot, and SELECT for interrupted-save candidates. Final-file existence/content is rechecked before return acknowledgement. See the root howtouse.txt for controls, recovery implications and current build limitations.
